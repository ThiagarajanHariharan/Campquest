## 2026-05-30 - Prevent Deep Cloning Redundancy on Fresh API Responses
**Learning:** The `api()` wrapper in `frontend/src/App.js` utilized deep cloning to prevent reference mutations. Applying deep cloning (`structuredClone` or `JSON.parse(JSON.stringify)`) unconditionally to all fresh `fetch` responses immediately after `await r.json()` is redundant because `.json()` already generates a fresh, detached JavaScript object. Unnecessarily cloning fresh network responses burns CPU cycles and counters performance goals.
**Action:** When caching API responses on the frontend, only apply deep cloning when returning cached objects from memory to ensure components receive separate object references. For fresh network responses, simply return the output of `await r.json()` directly.
