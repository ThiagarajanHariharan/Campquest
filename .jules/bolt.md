## 2024-11-20 - Concurrent Promise Execution
**Learning:** Independent PostgreSQL database queries inside asynchronous Express route handlers were executed sequentially using consecutive `await` statements (e.g., `activitiesResult = await pool.query(...)` followed by `statsResult = await pool.query(...)`), which unnecessarily delayed the response. Validation queries (like checking if a user exists) must still be awaited first.
**Action:** When independent queries are executed in a handler, group them inside a `Promise.all()` block (e.g., `const [activitiesResult, statsResult] = await Promise.all([query1, query2])`) to run them concurrently, optimizing the total response time. Include the comment `// OPTIMIZATION: Concurrently fetching independent data` alongside this change.
